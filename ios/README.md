# Enve Family for iPhone

Native SwiftUI client for the Enve Family Dashboard server (`../server.js`). The server stays the source of truth for household data and connected calendars; the Pi uses the native touch display.

- iOS 17+, Swift 6, iPhone, portrait and landscape
- No third-party dependencies
- The project is generated by XcodeGen. `EnveFamily.xcodeproj`, both targets' `Info.plist`, and both `.entitlements` files are generated and git-ignored. Use `generate-project.sh`: the installed XcodeGen 2.45.4 serializes nested App Groups capability attributes as a string, which the script corrects after generation.
- Two targets: the `EnveFamily` app and the embedded `EnveFamilyShare` Share Extension. `Shared/` is compiled into both.

## Generate and build

```bash
cd ios
sh generate-project.sh
xcodebuild -project EnveFamily.xcodeproj -scheme EnveFamily \
  -destination "platform=iOS Simulator,name=iPhone Air" build
```

Run the server from the repo root with `npm start`. In the simulator the default address `http://127.0.0.1:4317` reaches it directly.

For Share Sheet tests on Simulator, Xcode's local ad-hoc signature strips the App Group entitlement. Sign the built simulator app and its extension with the generated group value before `simctl install`:

```bash
sh sign-simulator-share.sh /path/to/DerivedData/Build/Products/Debug-iphonesimulator/EnveFamily.app
```

On a physical phone, complete first-run setup on the server device, then start the server so it listens on the network, e.g. `HOST=0.0.0.0 npm start`. Enter `http://<server-LAN-IP>:4317` in the app. It opens directly in no-password mode; otherwise sign in with the household password or PIN, or your individual adult account. iOS asks for Local Network permission the first time.

## Connection and security

- The server address is stored in `UserDefaults` and can be changed in Settings or from any connection error.
- When sign-in is enabled, the sign-in name and password or PIN are sent only in the `/api/login` request body and stored in the Keychain (per server address, this device only). Existing saved access keys remain readable for legacy installations. The server's session lives in memory, so after a server restart the app signs in again with the saved credentials.
- Session and edit-PIN cookies are kept in memory and attached by hand, because the server marks them `SameSite=Strict`.
- When a household edit PIN is set, a change that returns `423` opens a PIN prompt and is retried after `/api/pin/unlock` succeeds.
- Data is reloaded on launch, when the app returns to the foreground, after every change, and with pull to refresh.
- The last good `/api/state` response is cached in Application Support (excluded from device backups, protected until first unlock) and is cleared by Forget Sign-In. When the server can't be reached, the app opens from that copy read-only and shows an offline indicator next to the Settings button.
- While offline, new local events, tasks, list items, and meals are queued on disk and sent in order on the next successful load. A queued create is only made when the connection failed before the request left the phone (or the app already knows it's offline); a timeout or server error is shown as an error instead. Each queued item is marked as sending on disk before it's sent, so one interrupted mid-send is shown as "not sent" for the person to retry or discard rather than retried automatically. Google/iCloud events, edits, completions, and deletes are never queued.
- While the app is active it also follows the server-sent `/api/changes` stream and reloads when another device changes something. Bursts are coalesced, a reload is skipped if one already started after the change arrived, and the stream reconnects with backoff (2–30 s) after errors, reloading once on reconnect. It is cancelled whenever the app leaves the active state.

## Share Sheet import

Choose **Enve Family** in the share sheet of another app (selected email text in Mail, a flyer in Photos, a PDF or `.ics` attachment, a Safari link, a note) to save it for import.

- Accepted: plain text, web links, images, PDFs, and calendar (`.ics`) files, up to 10 attachments per share. Text and links from one share are combined into a single text item; each photo, PDF, or calendar file becomes its own item.
- iOS doesn't let a Share Extension open its app, so the extension only saves the items and says to open Enve Family. It never contacts the server and never reads the server address, sign-in, or Keychain.
- Items are saved privately in the App Group container (`ShareInbox/<UUID>/`, excluded from backups, protected until first unlock). Each is written to a staging folder and moved into place, so the app never sees a half-written item. Folder names must be canonical UUIDs and file paths are never taken from shared names, so shared file names can't escape the inbox.
- Limits match the import screen: files must be 5 MB or less after preparation, photos are converted to JPEG against a white background (longest edge 2560 px) in the extension, `.ics` and text must be UTF-8, and PDFs must start with a PDF header. At most 20 items wait at once; a share beyond that is refused with a message to review the waiting ones first.
- The app checks the inbox on launch, when it returns to the foreground, and when it finishes connecting. New items open the Import sheet once when no other sheet is showing; the Calendar tab also shows a "shared items to review" row while any are waiting.
- In Import, **Shared to Enve Family** lists the waiting items. Choose Import as, then **Find Drafts**: the item is sent to `/api/import/drafts` like any other import and the drafts appear for review in the normal editors. Nothing is saved automatically.
- An item is removed only when every draft found from it has been saved (or every list item added), or when you swipe to discard it. Failed requests, empty results, discarded drafts, or closing Import leave it waiting. Re-running Find Drafts on corrected text keeps it linked to the shared item.
- An item can't be sent twice at once: its button is disabled while its request is in flight, including after Import is closed and reopened.
- Items whose files are missing or malformed are listed as unreadable with a Discard button. Staging folders left by an interrupted extension are cleared after an hour.

### App Group signing on a physical iPhone

The Share Sheet handoff passed a simulator UI test with both targets signed with the App Group entitlement. A physical iPhone build also needs an Apple development team and an App Group registered to that team.

1. In `project.yml`, set `ENVE_APP_GROUP` and the matching App Groups entitlement in both targets to a group ID registered for your team. The example is `group.com.enve.family`. Also choose bundle identifiers available to your team; the extension's must stay prefixed by the app's (`<app-id>.share`).
2. Run `sh generate-project.sh`. The group is written into both entitlements files and each target's `Info.plist` as `EnveAppGroup`, which the code reads at runtime.
3. In Xcode, select your team for both the `EnveFamily` and `EnveFamilyShare` targets (Signing & Capabilities). With automatic signing Xcode registers the App ID, the extension ID, and the App Group and adds the group to both profiles. If it doesn't, add the group under Certificates, Identifiers & Profiles and enable App Groups on both App IDs.
4. Build and run the `EnveFamily` scheme; the extension is embedded and installed with the app.

If the group is missing or mismatched, the extension shows "Sharing isn't set up for this copy of Enve Family" and the app shows the same message under Import → Shared to Enve Family.

## Server API limits

These come from `server.js` as it stands; the app doesn't work around them.

- Outlook and subscribed (ICS) calendars are read-only. Google events are editable only on calendars the server marks writable; iCloud events only when the server reports them editable (not recurring, no invitees).
- Google and iCloud events have no repeat rules or per-occurrence edits through the API.
- Only new meals are queued offline; meal edits, deletes, meal types, suggestions, and grocery adds need a connection.
- A repeating meal's repeat rule changes through a this-and-later edit. A single meal can be changed into a repeating meal when edited.
- Suggestions skip slots that already have a meal. Ingredient exclusions are word matches for saved recipes and built-in ideas; cloud ideas only receive the words as a request. None of them is an allergy check. A plan or grocery request covers at most 28 meals.
- Cloud ideas need `OPENAI_API_KEY` on the server. The server sends the chosen days, meal types, servings, and words to leave out to OpenAI. The app allows at most 14 open slots per cloud request, counting days outside the loaded plan as open, and shows the server's error otherwise.
- Rotations need a repeating, dated chore assigned to a household member and allow up to eight people; rotating chores can't be claimable.
- Tasks can't be edited after creation; the only task updates are complete, skip, and claim.
- Rewards and goals can't be edited, only created and deleted.
- List items can't be renamed; list names can't be changed.
- `/api/state` accepts at most 43 days, so the app loads the visible calendar range plus the meal week in one request.
- Connecting calendar accounts (Google/Outlook OAuth, iCloud app passwords, ICS feeds) is left to the web dashboard on the server computer: OAuth callbacks point to `localhost` and iCloud setup must come from the server itself.
- Import files must be 5 MB or less. Photos are converted to JPEG (longest edge 2560 px) in memory before upload; HEIC files from Files are converted the same way. OCR runs on the server and can take up to two minutes.
- Recipe photo upload, photo frame uploads and deletion, and edit-PIN management remain web-only.
- Reminders only cover the calendar range the app last loaded (the visible weeks plus the meal week), because there's no background refresh or push. Opening the app keeps them current.
- Search, weather, and photo list responses are read tolerantly (flat or grouped result arrays; common temperature/summary field names), since the app only displays them.
- `/api/changes` only says that something changed, so each signal reloads the full `/api/state` range.
